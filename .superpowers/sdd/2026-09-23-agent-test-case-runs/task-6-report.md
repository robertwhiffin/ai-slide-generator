## Rulings (state machine)
1. **Candidate run joins the one gate.** It reads the saved draft under `lock_version` exactly as the probe does; a concurrent Save would only turn it into a 409. It is refused **with no request ID** while *any* field of the role is unsaved (`testRunCandidateUnsaved`), stricter than the probe's endpoint-only rule, because the run assembles the whole saved candidate (prompt, rules, overlay, model); the reducer repeats the refusal as a backstop. A 409 `stale_draft` goes through the existing `mergeConflict` (the probe path), so the conflict banner, Reload server and Keep local are reused; the panel adds one message.
2. **Baseline rerun joins the gate.** It is a bounded model call that writes evidence; a second in-flight flag would be a second gate. Cost: Save is blocked for the rerun's duration (up to the 120 s test runtime).
3. **Case create/retire join the gate.** They are writes; joining keeps one in-flight write and serialises P3's add-then-retire. Cost: a short Save block.
4. **Case-list read is not gated** (the #266 catalog precedent, C15). It takes an ID from the one counter only to drop out-of-order answers; a case write settles the list and invalidates an in-flight read (M19). It is **lazy** (a click), which keeps "issues exactly one read when mounted" and every Task 4 `allGets` backstop unchanged and still counting every GET.
5. **Evidence coherence** (like `settleProbe`): role, case and kind must match; a candidate run must also match the lock sent and the saved `candidate_hash`. No hash check for a baseline (a publication since load would false-alarm).
6. **Plan signature deviation:** two named execute clients instead of `executeTestRun(agentKey, testCaseId, isCandidateRun)`, because only the candidate sends a lock.
7. No second state machine, counter, gate, conflict model or autosave was added. View state only (selected case, open view, add form, retire confirm) lives in the panel.

## Concerns
1. **Evidence is session-local.** The UI never reads run history: after a reload the panel says "No run yet" even when stored runs exist. `getTestRun` and `listTestCaseRuns` are implemented and parser-tested but unused. Loading the latest run on case selection is a small follow-up (and would add a counted GET).
2. **No supersede (PUT) control.** Per P3 the UI offers add then retire; the update route is not exposed, so editing a case's payload means a new name.
3. **Lazy load costs a click per role.** Chosen to keep the mount-read backstops intact (ruling 4); an auto-load on role selection would need those backstops re-baselined.
4. **Baseline rerun and case writes block Save** while in flight (rulings 2–3).
5. **Candidate refusal is broader than the probe's** (any unsaved field, not just the endpoint). Deliberate; flagging because it differs from #266.
6. `min-w-0` was added to the aside's class so `<pre>` blocks scroll inside the 260 px track; no grid or width changed.
