## 3. Standing instructions for every task dispatch

Carried into every brief, because each one is a defect this branch already paid for.

1. **Never `pip install`.** Shared pyenv site-packages; an install corrupts sibling agents'
   runs. Interpreter is `~/.pyenv/versions/3.11.0/bin/python`.
2. **No git commands, not even read-only ones.** A `git show` in this shared tree destroyed a
   sibling agent's uncommitted work and cost ~15 applied findings. The controller commits.
3. **Re-derive every anchor by grep before using it.** Anchors drift *during* a build, not
   only between them: inside ws4d alone `poll_chat` moved `:669` → `:691`, `restore_version`
   `:2222` → `:2493`, `duplicate_slide` `:2850` → `:3353`. A reviewer's correction of an
   anchor is not evidence — `get_system_client()` is at `agent_factory.py:67`, the plan says
   `:56`, a review "corrected" it to `:57`, and both are docstring prose.
4. **Locate constructs by a distinctive bare TOKEN, never a paren-anchored prefix.** This
   codebase passes functions by reference, so `mark_dirty(` finds nothing where `mark_dirty`
   finds it. Three agents including the controller have made that exact mistake.
5. **Sabotage-verify every guard, and verify the sabotage landed on the executed path.** A
   sabotage that misses its target is indistinguishable from a test that cannot fail. **Read
   sabotage results by which tests fired, never by how many.**
6. **Adding a paired assertion and verifying the pair can fail are SEPARATE steps.** Three
   steps: add the guard, pair it, then sabotage the pair and read which assertion fired.
7. **Commit before sabotaging.** Restoring a file to its committed state to undo a sabotage
   also wipes uncommitted work in that file; that produced a false self-report on ws4d twice.
   Revert a sabotage by targeted edit, and re-read every claim from the committed blob.
8. **When the defect already ships, write the test RED FIRST** and confirm it fails before
   fixing anything. §4.6's inert re-review had fourteen green tests over it precisely because
   nobody did.
9. **`chat_service.py:32` gates COLLECTION of the entire unit suite** via
   `tests/unit/conftest.py` → `session_manager` → `src/api/services/__init__.py`. Reshape it
   and the suite stops collecting rather than failing.
10. **Ruling R2 binds and this is the last chance to break it by accident.**
    `src/services/agent.py`, `src/core/prompt_modules.py` and
    `src/services/design_system_compiler.py` are **never modified** — read and import freely,
    private names included. The two recorded exceptions (ws4a's `merge_css`, ws4c importing
    `UNTRUSTED_DATA_NOTICE`) are not widened.
11. **Frontend type-checking is `npm run typecheck`, never `npx tsc --noEmit`** —
    `frontend/tsconfig.json` is a solution file, so `--noEmit` checks zero files and exits 0.
12. **Report failure CAUSES, never counts**, and a count that will be acted on is measured
    without a `head`, a `sort -u` or a `set()` between the data and the number.
13. **No layer-3 assertion may be weakened to accommodate a placeholder prompt.** The skills
    ship substantive but un-prompt-engineered instruction text by design. If an assertion is
    tempting to weaken, skip the test and record why. A skipped honest test beats a passing
    dishonest one.

### The six fake-guard shapes, from `.ws4d-PLAN-CORRECTIONS.md`

Every one was found by sabotage, never by reading. A test of each shape passes when:

| Shape | Passes when… |
|---|---|
| absence-assertion (§18) | the code never ran at all |
| tautological-default (§22) | the code ran but carried nothing |
| mixed shape/behaviour (§24) | a *different* assertion in the same test fired |
| inert pair (§26) | the paired direction is satisfied by something else |
| involution (§29) | the transformation applied twice is the identity, so the defect cancels |
| unreachable stub (§31) | the stubbed outcome is one production can never produce |
| self-comparison (§32) | both sides of the comparison are the same object and move together |

> **"The check found something" is far weaker than "the check found what it should have found."**

**§31's diagnostic, which is the one to apply here:** ask what *real* input would produce the
outcome your stub returns. If you cannot name one, the test is measuring your fixture rather
than the code.

**Measured by the controller, after probe A contradicted the plan.**

reviewInProgress = releasedPositions.size === deckSpec.slides.length && !turnComplete

So the flag as specified always evaluates `0 === N`, and its headline test — *"the flag turns

**Ruling E-2: add a task, E0, and run it before E2b.** This is not scope creep — it is the
