### C-A1-2 (REJECTED scout correction) — the plan's `bad {{{` string is not wrong; it is input-dependent

A scout reported the plan's measured `'bad {{{\n}}}'` was wrong and should be `'bad {{{}}}'`.
**Re-probed: both are right, and which one you get depends on the input's trailing whitespace**,
because `tinycss2.serialize` echoes source whitespace:

```
input "bad {{{"    -> serialize([node]) == 'bad {{{}}}'
input "bad {{{\n"  -> serialize([node]) == 'bad {{{\n}}}'
```

**Executor action: do not pin that exact string in a test at all.** If you must, choose the input
explicitly and assert against the value for that input. The plan's *structural* claim is what
matters and it holds: malformed input yields a `qualified-rule`, not an exception, so
`parse_css_blocks` must not assume a parse failure path.
