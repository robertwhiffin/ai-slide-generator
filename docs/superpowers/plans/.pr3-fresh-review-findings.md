## FATAL — Phase 5 as written cannot build a deck

**F1 ✅ A static `builder -> build_reviewer` edge collapses N branches into ONE and drops
the payload.** My probe: 3 builders fanned out via `Send`, reviewer invoked **once**,
input keys `['seen']` only — no `position`, no `html`. So:
- `build_reviewer_node`'s first line `payload["position"]` raises `KeyError`
- one review per *batch*, not per slide → breaks the "one reviewer per slide writes one
  row" no-contention invariant (spec §5.5) and the n-not-3n cost model (§5.2.4)
- the per-slide fix path never fires

Fix: re-fan-out with a conditional edge from `builder`, returning
`Send("build_reviewer", {**payload, "html": ..., "scripts": ...})`. The builder must
carry its payload forward in a scratch key. **This is my error from pass 3** — I wrote the
"reached by the static edge, so it receives the merged payload" claim without probing it.

**F2 ✅ The `fix_map` tombstone doesn't work: `bool({0: None}) is True`.**
`fix_reviewer_node` writes `{"fix_map": {position: None}}` and `foreman_router` tests
`if state.get("fix_map")` → always truthy → routes to fixer forever → `fixer_node`'s
`min()` over an empty sequence raises `ValueError`, then `GraphRecursionError`.
Fix: `if any(e is not None for e in state.get("fix_map", {}).values())` at both sites.
**Also my error from pass 3**, and the plan's own comment states the intent the code
contradicts.

**F3 The sequential fixer re-fixes positions.** `fixer_node` picks `min()` of all pending
fixes but `fix_reviewer_node` clears only `fix_target`, so higher positions get re-fixed —
reviewer measured each position fixed twice, deck reviewer firing twice. Breaks the
headline "one fix round maximum". Fix: mark entries in-flight on dispatch, or fan the
fixer out per-position via `Send` like builders.

## CRITICAL — production-only failures the described tests would pass

**F4 `recursion_limit` is never set; default is 25.** Foreman-centric topology burns 3-4
supersteps per fix round, so a 10-slide deck with fixes dies with `GraphRecursionError`.
Must be set explicitly at every invoke site alongside `max_concurrency`, sized for 31+
slides.

**F5 A sync-only checkpointer breaks `astream`.** Task 1.4 Step 3 specifies only sync
methods, but line 123 contemplates `astream`, and `BaseCheckpointSaver`'s async methods
raise `NotImplementedError`. Either declare the graph sync-only (defensible —
`chat.py:368` already threads it, `job_queue.py:202` is sync) or implement
`aget_tuple`/`alist`/`aput`/`aput_writes`. Also: `delete_thread` already exists on the base
class and is the natural `clear_graph_thread`.

**F6 No per-turn state reset — turn 2 sees turn 1's `landed_positions`.** `thread_id` is
per session, reused across turns, so reducer state accumulates. Passing a fresh value does
NOT reset it (reducers merge). Measured: turn 2 sees `landed=[0,1,2]`, so
`next_dispatch_batch` returns `[]`, `all_positions_committed` is true, and the graph goes
straight to deck review **without building anything**. `findings` grows unboundedly too.
Needs per-turn `checkpoint_ns`, turn-scoped keys, or reset nodes — and a second-turn test,
which no described test covers.
