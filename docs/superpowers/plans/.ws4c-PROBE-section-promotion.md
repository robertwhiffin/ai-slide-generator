# ws4c C6 — the section-promotion probe, RUN and MEASURED

**Measured 2026-09-13 by the controller**, Playwright 1.57.0 + bundled chromium, driven as a library
(no dev server, no `testDir`, no config — `page.setContent()` is enough, which is why the plan's
"the spec must live inside `frontend/tests/`" constraint does not apply to this measurement).

C6's implementer reported the probe as **not run** (no browser or dev server available) and shipped
`extract_section` **without** re-parenting, recording the behaviour as unverified. That was the right
call under its constraints — the brief forbade implementing re-parenting on an assumption. The
controller then ran it. **The divergence is real, and re-parenting is required.**

## Why this matters

`SLIDE_WRAPPER_TAGS` is `{"section", "article"}` only: `<div>` and `<main>` are deliberately
excluded. So a template wrapping its slides in a non-promoting tag keeps that wrapper's styles
**outside** the extracted section. §M5 is explicit that CSS travels whole and an undefined
`var(--…)` is the **measured washout defect** — a model once dropped 57 `var(--…)` definitions and
washed out preview and both PPTX export paths. A silently unstyled section is the same failure
arriving from the other direction.

## Probe 1 — directly inherited properties

CSS: `main { padding: var(--slide-pad); background-color: rgb(10,20,30); color: rgb(240,240,240);
font-family: "Georgia", serif; }` with `:root { --slide-pad: 48px; }`.

    IN SITU     : {"padding-top":"0px","padding-left":"0px","background-color":"rgba(0, 0, 0, 0)","color":"rgb(240, 240, 240)","font-family":"Georgia, serif","border-top-width":"1px"}
    EXTRACTED   : {"padding-top":"0px","padding-left":"0px","background-color":"rgba(0, 0, 0, 0)","color":"rgb(0, 0, 0)","font-family":"Times","border-top-width":"1px"}
    REPARENTED  : {"padding-top":"0px","padding-left":"0px","background-color":"rgba(0, 0, 0, 0)","color":"rgb(240, 240, 240)","font-family":"Georgia, serif","border-top-width":"1px"}

    DIVERGENT (in-situ vs extracted)  : ["color","font-family"]
    DIVERGENT (in-situ vs reparented) : []

**`color` and `font-family` are LOST. Re-parenting closes it completely.**

## Probe 2 — the plan's SPECIFIC claim: a custom property defined on the wrapper

CSS: `main { --slide-pad: 48px; --brand: rgb(1,2,3); }` and
`.slide { padding: var(--slide-pad, 0px); background-color: var(--brand, rgb(255,255,255)); }`.

    IN SITU   : {"padding-top":"48px","padding-left":"48px","background-color":"rgb(1, 2, 3)"}
    EXTRACTED : {"padding-top":"0px","padding-left":"0px","background-color":"rgb(255, 255, 255)"}
    REPARENT  : {"padding-top":"48px","padding-left":"48px","background-color":"rgb(1, 2, 3)"}
    DIVERGENT (in-situ vs extracted): ["padding-top","padding-left","background-color"]

**Padding collapses 48px → 0px and the brand colour falls back to white.**

## The mechanism — and it corrects the plan's expectation list

The plan expects the divergence in *"`padding` via a custom property defined on the wrapper, plus
`font-family`, `background-color`, `color`"*. Measured, that list is **partly wrong**, and the
correct statement is sharper:

**Only INHERITED things are lost.** `color` and `font-family` are inherited properties, so they are
lost directly (probe 1). **Custom properties are also inherited**, so a `var()` consumed by the
section resolves to its **fallback** once the wrapper is gone — which is how a non-inherited property
like `padding` or `background-color` loses its value too (probe 2). A wrapper's own box properties
that the section does not consume through a variable do **not** diverge: `background-color` set
directly on `main` shows as `rgba(0,0,0,0)` on the section **both** ways in probe 1, because
`background-color` is not inherited.

So the failure is not "the wrapper's styles are lost" but **"everything the section inherits from the
wrapper, including every custom property it resolves, is lost."** That is strictly broader than the
plan's list where variables are involved and strictly narrower where they are not.

## The required fix, and how to guard it

`extract_section` **must re-parent**: return the section wrapped in its non-promoted ancestor chain,
with the ancestors' other children stripped. **Never** resolve the divergence by pruning or
rewriting the template's CSS — §M5 is explicit that CSS travels whole.

**The guard is a Python test, not a browser test.** The browser measurement above is the
*justification*; the unit test asserts the *markup contract*, which is what `extract_section` owns:

- given a layout whose `.slide` roots sit inside `<main>` (or a bare `<div>`), the returned markup
  **includes that ancestor chain**;
- the ancestors' **other children are stripped** (sibling slides do not come along);
- the section's own markup is still **byte-for-byte verbatim** inside the wrapper;
- a section whose ancestors are all promoting tags (`section`, `article`) is returned **unwrapped**,
  exactly as today — re-parenting must not add a wrapper that was not there.

Making this a Playwright spec was considered and rejected: `frontend/tests/` is Playwright's
`testDir`, so a new spec there falls under ws4a's `test_e2e_matrix_covers_specs.py` guard and would
have to be added to the matrix or to `DELIBERATE_EXCLUSIONS` — a CI-policy change inside a task that
has no other CI work. The probe script is recorded here instead, and it is re-runnable in about
thirty seconds from `frontend/` with the Playwright library.

## Re-running it

Drop the script below in `frontend/` (so `require('playwright')` resolves against
`frontend/node_modules`), run `node <file>.cjs`, delete it. It needs no dev server and no config.

```js
const { chromium } = require('playwright');
const CSS = `
  main { --slide-pad: 48px; --brand: rgb(1,2,3); }
  .slide { padding: var(--slide-pad, 0px); background-color: var(--brand, rgb(255,255,255)); }
`;
const SECTION = `<section class="slide"><h1>T</h1></section>`;
const PROPS = ['padding-top','padding-left','background-color'];
(async () => {
  const b = await chromium.launch(); const page = await b.newPage();
  const read = async (html) => { await page.setContent(html);
    return page.evaluate(p => { const cs = getComputedStyle(document.querySelector('.slide'));
      const o = {}; for (const k of p) o[k] = cs.getPropertyValue(k); return o; }, PROPS); };
  const inSitu = await read(`<style>${CSS}</style><main>${SECTION}</main>`);
  const extracted = await read(`<style>${CSS}</style>${SECTION}`);
  console.log('IN SITU   :', JSON.stringify(inSitu));
  console.log('EXTRACTED :', JSON.stringify(extracted));
  console.log('DIVERGENT :', JSON.stringify(PROPS.filter(k => inSitu[k] !== extracted[k])));
  await b.close();
})();
```

Note `page.evaluate` takes `(pageFunction, arg)` — passing a third argument, or a function as the
second, throws instead of measuring.
