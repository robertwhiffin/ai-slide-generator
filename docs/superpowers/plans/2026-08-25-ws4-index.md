## Why this is five plans and not one

The single-PR plan was reviewed to the `doc-review-loop` skill's 3-round maximum, with 11 fix
passes. It did not converge:

| Round | Findings | Blocking |
|---|---|---|
| 1 | 21 | 5 |
| 2 | 31 | 4 |
| 3 | 30 | **9** |

Severity never decayed, and in round 3 **four of the nine blocking findings were regressions the
loop's own earlier fixes had introduced.** The cause was measured, not guessed: the plan carried
~195 fenced blocks of full inline implementation (390 fence lines), so a fix agent editing one block could not see
the dependency graph and would satisfy a finding while breaking a neighbour. Examples that
recurred: inventing a field on a frozen Pydantic schema to wire a value; calling a domain method on
the dict a service returns; defining one module twice in two tasks with incompatible types.

**Two things change here, and both matter more than the split itself.**

1. **The split.** Five plans, five PRs, each independently mergeable and each producing working,
   testable software on its own. Small enough that a reviewer can hold one in their head.
2. **The style.** These plans carry **contracts, file:line anchors, invariants and test *intent***.
   They carry code **only where the code is the decision** — a reducer, a SQL predicate, a
   validator, a schema. They do **not** carry full function bodies for work an engineer can write
   from a stated contract. That is the density that made the last plan unreviewable.

**What is deliberately kept from the superseded plan:** every *decision*, every verified anchor,
and every probe result. Those survived review; it was the inline code that did not. The superseded
plan stays in the repo as the reference for anything this index summarises.

## Global Conventions — inherited by all five plans

### Environment

- **Interpreter: `~/.pyenv/versions/3.11.0/bin/python`.** Shared pyenv site-packages.
- A gitignored in-tree **`.venv` carries the PRE-PR2 stack** (langgraph 1.0.3, mlflow 3.6.0, no

  is a solution file (`{"files": [], "references": […]}`), so `--noEmit` against it checks **zero
  files** and exits 0 regardless of errors. Measured.

### Design invariants

- **Reviewers write rows, builders never do.** An unreviewed slide never persists — one exception, a
  terminal-failure placeholder (§I).
- **Exactly one fix round.** A survivor becomes a surfaced finding.
- **Verification is per-row**, content-hash keyed, **merged never overwritten** (PR1). A record
  belongs to a **slide, not a position** — it travels with its slide on reorder. A deck review
  verdict is the opposite: it is about an *ordering* (§F4).
- **Foreman state lives in the checkpointer**, never in process memory.
- **`thread_id` on every invoke.** Omitting it raises `ValueError: Checkpointer requires one or more
  of the following 'configurable' keys`.
- **No `recursion_limit` config.** The 1.2.10 default is **10007** (verified); the superseded plan's
  ~50 would have made the graph fail *earlier* than shipping no config.
- **Sync only.** The saver implements sync methods; `send_message_streaming` is a plain `def`
  generator (`chat_service.py:825`), `job_queue.py:202` iterates it synchronously, routes push it
  through `asyncio.to_thread`. **Never call `astream`.** Consequence: **`Send(timeout=)` is unusable**
  — probed, it raises `ValueError: Node timeouts are only supported for async nodes because sync
  Python execution cannot be safely cancelled in-process`. Stall detection uses state-recorded
  timestamps, and that is the only option.
- **Brand bytes never pass through a model.** The architect **assigns** a template section;
  deterministic code **extracts** it (§M3). Never take `token_css` or layout bytes from model output.
- **Never hardcode the safe-area numbers in a skill.** Prompt assembly injects
  `_SLIDE_FRAME_CONSTRAINTS` when the resolved style lacks it (§L5's third case).
- **Concurrency cap 15**, ascending dispatch. **Retries jump the queue ahead of higher unstarted positions** by
  construction — ascending order alone puts a failed position ahead of positions it hasn't started yet.
  With all lower positions already completed, a retry may not jump ahead of anything.
- **Migrations run PRE-FORK** in `packages/databricks-tellr-app/databricks_tellr_app/run.py::init_database`,
  not the FastAPI lifespan; each step `raise SystemExit(1)` on failure, so an app that reaches
  RUNNING is proof the migration applied (§L8). **Periodic loops are the opposite** — they belong in
  the lifespan, next to `mark_timed_out_jobs_loop`.
- **`UVICORN_WORKERS` defaults to 4** (`run.py:128`). Anything periodic runs in all four and must
  claim its work atomically.
- **`VERSION_LIMIT = 40`** (`session_manager.py:1859`) — nothing may FK to `slide_deck_versions`.

### Reserved-key and shape constraints on any verdict written to a row

- **`error` is reserved.** `is_placeholder_record` (`src/api/services/slide_repository.py:41-61`)
  returns True when the record's top level **or any verdict value inside it** has `error is True`.
- **Findings stay inside the `{content_hash: verdict}` shape.** `get_verification_map`
  (`session_manager.py:1793-1811`) flattens every row's record into one dict that feeds
  `create_version`, so anything keyed otherwise is baked into save points and lost.
- **`SlideWriter.write_slide(verification_record=None)` PRESERVES the existing record** — verified at
  `slide_repository.py:84-110`. Pass an explicit record when writing a fresh verdict. It also takes a
  `slide_id` parameter.

### Verified runtime facts — do not re-derive, do re-probe if you doubt

Re-executed on langgraph 1.2.10 during planning:

| Fact | Measurement |
|---|---|
| Superstep barrier | An orchestrator sending batches of 2 over 5 positions woke exactly 4 times: `[]`, `[0,1]`, `[0,1,2,3]`, `[0,1,2,3,4]` — never per worker |
| A `Send`-reached node sees ONLY its payload | Saw `['batch','position']`; no state key visible |
| A static edge out of a `Send`-reached node collapses N into ONE | 3 builders → **1** invocation, plain state, no payload |
| Re-fanning with a conditional edge | 6 builders → **6** reviewers, each with its own payload |
| `bool({0: None})` is `True` | so a dict reducer cannot delete a key; a tombstone still reads as pending |
| Turn-2 state accumulates | turn 2 passing a fresh empty set still saw turn 1's values; a fresh `checkpoint_ns` does not reset it either |
| **Undeclared keys are silently dropped** | a node returning an undeclared key produces no error and the write is discarded — and an undeclared *input* key never reaches the node. This caused three separate blocking findings; treat `GraphState` as the exhaustive contract it is |

### Per-plan execution requirements

Every plan is executed with **`superpowers:subagent-driven-development`** plus
**`executing-plans-tellr`**. Non-negotiable practices, each of which caught a real defect on PR1/PR2
or during this review loop:

- **A corrections pre-pass before task 1**, written to that plan's own `.PLAN-CORRECTIONS.md`, which
  **overrides the plan**. Every dispatch brief points at it.
- **Sabotage-verify every guard.** Break the line a test protects and confirm it goes red — then
  confirm your sabotage landed on the executed path, because a sabotage that misses its target looks
  identical to a test that cannot fail.
- **Tell subagents the failure *cause*, never the count.**
- **Re-probe every external-state fact a subagent volunteers.** Five fabrications clustered there on
  PR1/PR2.
- **Verify every self-report.** Across this review loop's 11 fix passes: one edited product code
  despite an explicit bar, three mis-classified findings as OVERTURNED with no contradicting
  evidence, one left a test with no assertion at all, one declared eight assigned findings "outside
  scope". Roughly half needed a correction pass behind them.
- **Sequence tasks that touch the same file**; parallelise only across distinct files.
