# PR3 plan — round-2 review findings (working file, not the plan)

## Blocking — must fix before PR3 can execute

1. ✅ VERIFIED **Checkpointer import/class/constructor all wrong.** Unpacked
   `langgraph_checkpoint_postgres==3.1.1`: module is `langgraph.checkpoint.postgres`
   (NOT a top-level `langgraph_checkpoint_postgres`);
   `__all__ = ["PostgresSaver", "BasePostgresSaver", "ShallowPostgresSaver", "Conn"]`
   — there is no `PostgresCheckpointer`; `__init__(self, conn: Conn, pipe=None,
   serde=None)` — no `connection_string=`, no `schema=` kwarg at all. `setup()`
   docstring: "MUST be called directly by the user the first time checkpointer is
   used" — the plan never calls it. **PR2's plan is also wrong here** (right class,
   wrong module), so no correct reference exists anywhere in the chain.

2. ✅ VERIFIED **PostgresSaver bypasses the OBO token hook — production breaks at
   ~60 min.** `provide_token` is a SQLAlchemy `do_connect` listener on the *engine*
   (`database.py:303-312`); `PostgresSaver` takes a raw psycopg connection, so it never
   traverses that listener. `TOKEN_REFRESH_INTERVAL_SECONDS = 50*60` with 1-hour
   expiry (`database.py:39-40`) only feeds the SQLAlchemy path. **This is a SPEC gap
   (§5.7 / §2.2), not just a plan gap** — the spec asserted the official saver was the
   cheap option precisely because psycopg3 was "mostly a connection-string change."
   Needs a decision: share the SQLAlchemy pool's connections, wrap with a
   token-refreshing Conn provider, or write a custom BaseCheckpointSaver over the
   existing engine.

3. **Checkpointer needs a `thread_id`** in `config={"configurable": {...}}` on every
   invoke; plan omits it everywhere. Also builds a *per-session* checkpointer, which is
   the wrong model (one shared saver + per-invocation thread_id) and opens a connection
   per session against a pool_size=80 engine.

4. **`add_edge("START", ...)`** — sentinel is `"__start__"`; must use the imported
   `START`. Compiles then fails.

5. **Every node/router signature is invalid for LangGraph** — nodes are called
   `node(state)` / `node(state, config)`; the plan uses extra positional params
   (`builder_node(state, config, idx)` etc.). `Send`'s payload becomes the node's whole
   input state, which conflicts with those same functions reading `state["deck_spec"]`.
   Unreconciled.

6. **`Send(("builder", pos, spec))`** — real signature is `Send(node, arg)`. Also
   `Send` objects must be returned from a conditional-edge router, not written into
   state under `builds_to_dispatch` (which nothing reads).

7. **No state reducers.** `GraphState` has no `Annotated[..., reducer]`, but N builders
   write `html`/`scripts`/`position` concurrently → `InvalidUpdateError: can receive
   only one value per step`. Designing fan-in reducers is the central state task and is
   absent.

8. **The concurrency design is unimplementable as drawn.** LangGraph runs supersteps
   with a barrier: the foreman re-runs only after *all* dispatched branches finish. So
   "as slots free take the lowest outstanding" and the release timeout cannot work, and
   the release timeout can never fire while a position is actually stalled. Real lever
   is `invoke(..., {"max_concurrency": 15})`, which gives the cap but NOT ascending slot
   allocation. Needs a different design (worker-branch pool over a checkpointed queue,
   or `defer=True` fan-in). Invalidates Phase 4 + much of 8.1, and their unit tests
   would pass against the service in isolation while shipped behaviour is
   "dispatch 15, wait for all 15, dispatch next 15."

9. **Foreman state is in-process** — `ForemanState` is never instantiated or persisted;
   Task 8.1 mutates an undefined `foreman_state` free variable. This is `self.sessions
   = {}` (PRD §12.1's named bug class) under a new name, contradicting the plan's own
   global constraint that foreman state lives in the checkpointer.

10. ✅ VERIFIED **`_run_output_safety_gate` called with the wrong signature.** Real:
    `(html_output, regenerate, session_id, on_retry=None)` where `regenerate` is a
    zero-arg callable the gate invokes; returns `(safe_html, retried)`. Plan passes
    `scripts` as the 2nd arg → `TypeError` on the unsafe path. Gate also only scans
    HTML, never scripts. And Phase 9.2 `git rm`s the file that defines it.

11. ✅ VERIFIED **Hand-rolled `<untrusted-data>` f-string reintroduces a fixed bug.**
    `src/utils/spotlight.py::spotlight()` exists and neutralises embedded delimiters
    (its docstring cites "review finding #7") + applies `cap_tool_output`. The plan's
    f-string does neither → builder HTML containing a closing delimiter breaks out.
